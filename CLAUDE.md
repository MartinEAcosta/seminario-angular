# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Angular 20 (standalone components, no NgModules anywhere) e-commerce-style course platform ("Udemix Learning"): browse/create/enroll in courses, cart, checkout via MercadoPago, video lessons via video.js, email/password + Google OAuth login. Personal portfolio playground.

Stack is Angular `20.3.x` + TypeScript `5.9.3`, still on **zone.js** (no `provideZonelessChangeDetection`). `tsconfig.json` runs `strict`, `strictTemplates` and `noPropertyAccessFromIndexSignature` — index-signature reads must be bracketed.

Backend is a separate repo (`seminario-angular-backend`, not in this workspace) — without it running, auth/login/course-creation/image-upload flows won't work; the app falls back to mocked data for browsing. Backend setup: clone it, `npm install`, create `.env` from `env.template`, `npm run dev` (serves on `localhost:4201`).

Runtime dependencies are deliberately few: Angular + `rxjs`, `video.js`, `@mercadopago/sdk-js`. No UI kit, no state library, no HTTP wrapper — don't add one without asking.

**Language**: code comments, spec docs and UI copy are in Spanish. Keep writing them in Spanish.

## Commands

- `npm start` / `ng serve` — dev server, `development` configuration (swaps in `environment.development.ts`, HMR off)
- `npm run build` — production build to `dist/seminario-angular`
- `npm run watch` — dev build with `--watch`
- `npm test` / `ng test` — Karma/Jasmine (`@angular/build:karma`)
  - Headless single run: `npx ng test --watch=false --browsers=ChromeHeadless`
  - Run a single spec: scope with `fdescribe`/`fit` in the spec file — this Karma config has no file-filter flag
- No lint script and no ESLint config in the repo.

**`ng test` cannot build at all** (pre-existing, not caused by your change). Root cause: `angular.json`'s test `styles` references `node_modules/@videojs/themes/dist/fantasy/index.css`, and `@videojs/themes` is in neither `package.json` nor `node_modules`. The `build` target only pulls `src/styles.scss`, so **production builds are fine** — only the test target is broken. Drop that style entry or install the package before trusting any test output.

Most are leftovers from renames the specs never followed.

## Working agreement

Never build a large amount of code on top of an unresolved question — either hand over what's already complete and say what's missing, or ask the specific blocking question (one decision at a time, with options and trade-offs). Small reversible judgment calls are fine: state the assumption and move on. Finish every part that does **not** depend on the open question first.

If something fails, is canceled, or loses access mid-task (a service, credential, permission, connection), say so immediately and again in the final report — never route around it silently. No work is closed until the user confirms it; don't mark it done on your own initiative.

## Conventions

Files are `<name>.component.ts|html|scss` (+ `.spec.ts`), class `<Name>Component`, selector `app-<name>`; services `<name>.service.ts`, state `<name>-state.ts`. Standalone is implicit — no component declares `standalone: true`. DI is always `inject()`, never constructor params. Public service methods are frequently arrow-function class properties.

**Page naming drift** — two styles coexist, split by feature, not by age:

- `-page.component.ts` / `class <Name>PageComponent`: all of `auth/pages/` (`forgot-password`, `reset-password`, `user-profile`, `verify-email`) and `teacher-request/pages/`.
- `-page.ts` with no class suffix: `@shared/pages` (`ExplorePage`, `about-page`, `not-found-page`), `payment/pages/buy/buy-page.ts` → `class BuyPage`, `course/pages/course-detail/course-page.ts` → `class CoursePage`.

Follow whichever the feature you're touching already uses; don't rename across the board.

**Schematics gotcha**: `angular.json` sets `standalone: false` for the component/directive/pipe schematics, so `ng generate component` emits NgModule-style code that matches nothing in this codebase. Write components by hand or strip the flag afterwards.

## Architecture

**Feature-folder structure**, per Angular's official style guide. Each feature under `src/app/<feature>/` typically contains its own `components/`, `pages/`, `services/`, `models/`, `state/`, and sometimes `guards/`, `resolver/`, `interceptors/`, `layout/`, `forms/`, `utils/`. Features: `auth`, `cart`, `category`, `course`, `enrollment`, `file`, `lesson`, `module`, `payment`, `shared`, `teacher-request`, `user`, plus top-level `mappers/` and `utils/`.

**Path aliases** (see `tsconfig.json`) — always prefer these over relative imports across features: `@auth/*`, `@course/*`, `@cart/*`, `@category/*`, `@enrollment/*`, `@file/*`, `@lesson/*`, `@module/*`, `@payment/*`, `@teacher-request/*`, `@user/*`, `@utils/*`, `@shared/*`, `@mappers/*`, `@guards/*`, `@interfaces/*`, `@variables` (→ `src/variables.scss`). Two of them aren't what the name suggests: `@interfaces/*` is a **4-way multi-target** (`course/models`, `auth/models`, `module/models`, `lesson/models`), and `@guards/*` resolves to `auth/guards/*`, not a top-level dir.

**Routing**: `app.routes.ts` is the root route table; each feature with routes exports its own `<feature>.routes.ts` (default export) lazy-loaded via `loadChildren`. Two exceptions ride in the initial bundle: `''` (`HomeComponent`) and `explore` (`ExplorePage`) are **eager** imports from the `@shared/pages` barrel. Router is configured with `withComponentInputBinding()` and scroll-position restoration, so route params/data arrive as component inputs. Guards use the functional `CanMatchFn`/`CanActivateFn` style; route data resolvers live in each feature's `resolver/` dir. The `**` wildcard renders the 404 page (`loadComponent` of `@shared/pages/not-found/not-found-page`, which is an `export default class NotFoundComponent`) instead of redirecting to home.

**State management**: no NgRx/store library — plain Angular `signal`/`computed`/`effect`/`linkedSignal` in `@Injectable({providedIn:'root'})` services. Many features extend the generic base class `src/app/shared/state/state.ts` (`State<T>`), which wraps state in `{ isLoading, error, data }`, provides `handleError`/`setIsLoading`/`resetState`, and auto-calls `resetState()` via an `effect` whenever `UserState.user()` goes null (so logout clears all feature state for free). Feature state services (e.g. `course/state/course-state.ts`) extend `State<FeaturePropsInterface>` and add feature-specific signals on top.

**Auth/session**: `UserState` (`@user/state/user-state.ts`) is the single session holder — private `_user`/`_token`/`_authStatus` signals exposed as `computed`s, token mirrored to `localStorage` under the key `x-token`, `defaultAvatarUrl = 'assets/user-profile.svg'`, and mutators `setUser`/`setToken`/`setAuthStatus`/`setEmailVerified`/`logout`. It holds **no forms** — form construction lives in `auth/forms/user-form-factory.ts`. `authStatus` is derived: `'checking' | 'authenticated' | 'not-authenticated'`. `AuthService.checkStatusResource` is an `rxResource` that hits `/auth/renew` the first time the service is injected; the auth guards deliberately ignore `authStatus === 'checking'` and wait for a real transition, so **every error path in `AuthService.handleAuthError` must settle `authStatus`** or the guards hang forever (see `specs/06-*`).

**Auth forms**: `auth/forms/user-form-factory.ts` is the shared factory — `userFieldsValidators` (including `fileMaxSizeValidator(2_000_000)` for the avatar), `buildProfileForm`/`patchProfileForm`, `buildRegisterForm`, `buildLoginForm`, `buildPasswordForm`, `buildResetPasswordForm` (same as the password form minus `currentPassword` — the reset token is what proves identity), the group-level `passwordsMatchValidator`, and `getPasswordStrength` (4-segment meter against `strongPasswordPattern`). **Two sources of truth exist**: `FormRegisterComponent` and `FormLoginComponent` do *not* use the factory — they build their `FormGroup` inline with different validators (`minLength(6)` instead of `strongPasswordPattern`, a local 3-segment strength computed), and `buildLoginForm` is currently dead. If you touch those forms, change the right one.

**Password recovery / email verification** (`specs/13-*`): `AuthService` covers `sendVerificationEmail()` → `POST auth/send-validation-email`, `confirmEmailVerification(token)` → `POST auth/validate-email/{token}` (calls `userState.setEmailVerified(true)` on success), `sendForgotPasswordEmail(email)` → `POST auth/forgot-password`, `resetPassword(token, newPassword)` → `POST auth/reset-password/{token}`, and `updatePassword(PasswordDTO)` → `PUT auth/password/`. The last three return `Observable<boolean>` with `catchError → of(false)`; `resetPassword` deliberately shows **no toast** — `ResetPasswordPageComponent` owns the error UI through a `panelState: 'form' | 'invalid'` signal that swaps in an inline "enlace no válido" card. Both token pages read the token via `route.snapshot.paramMap.get('token')`, deliberately **not** via `input()` despite the global `withComponentInputBinding()`. `ForgotPasswordPageComponent` reuses the 60s `RESEND_COOLDOWN_SECONDS` pattern from `email-verification-banner`. The backend contract for forgot/reset is **assumed, not verified** (same situation as the spec-10 teacher-request DTO).

**`auth.routes.ts` ordering is load-bearing**: `forgot-password` and `reset-password/:token` are declared **before** the `path: ''` + `AuthLayoutComponent` block, because that block's `'**' → redirectTo login` child intercepts any sibling segment the router would otherwise reach afterwards. Don't reorder those entries. `me` (`UserProfilePageComponent`, `AuthenticatedGuard`) and `verify-email/:token` (public — the token is the credential) sit after it.

**Profile & security UI**: lives in `auth/pages/user-profile-page/`, **not** under `user/` — `src/app/user/` only holds `state/user-state.ts` and `components/user-profile-dropdown/`. It's a single page with three stacked `<article>` cards (avatar hero, "Datos de la cuenta", collapsible password card), no tabs and no child routes. The avatar goes through `FilePreviewControl` + `applyFileControlChange`/`clearFileControlChange` from `@file/utils/file-control-change`; `email-verification-banner` takes an `input flush` so it can nest inside the hero without its own border/radius.

**`User` model after `specs/12-*`**: `username` is gone everywhere. `User` is `{ id, first_name, last_name, email, isEmailVerified, role: 'student'|'teacher'|'admin', avatar_url, id_file }`; `UserDTO` has everything optional except `email` (plus `password?`); `PasswordDTO` is `{ currentPassword, newPassword }`. `AuthMapper.mapFormToUserDTO` emits `first_name`/`last_name`/`email`/`password` and is also used by `form-login`, which therefore produces `first_name: undefined`.

**OAuth**: `AUTH_PROVIDER` (`auth/auth.provider.ts`) is an `InjectionToken<AuthProvider>` wired in `app.config.ts` to `GoogleAuthService` — add further providers behind that interface (`ready`/`prepare`/`signIn`/`onCode`) instead of injecting a concrete service. `GoogleAuthService` lazily injects Google's GSI script and runs `initCodeClient` in popup mode; the auth code is exchanged server-side via `POST /auth/login/google`. Note: it imports `environments/environment.development` directly rather than `environment`, so the dev client id ships in production builds too.

**Course page** (`specs/11-*`): `course/pages/course-detail/course-page.ts` (`class CoursePage`); `CourseDetailComponent` was deleted. New components `course-hero`, `course-instructor` (`variant: 'inline' | 'card'`) and `course-purchase-panel` (sticky aside that rides up over the dark hero band via a negative `margin-top`), exported from `course/components/index.ts`. The page owns **two** `rxResource`s — `courseService.getDetailedById(id)` and `moduleService.getModulesByCourseId(id)` — and the modules are fetched **only there**, then passed by input to the hero, `list-of-content` and the panel's `lessonsCount`; `list-of-content` and `modules-accordion` no longer fetch anything themselves. Shared util `@utils/module-stats.ts`: `computeModuleStats` returns `totalDurationMinutes: null` when **any** lesson lacks `duration_minutes` (a partial total would be a false number), and `formatDuration` renders `Xh Ymin`. `spots_remaining` is display-only — nothing stops a sold-out course from being added to the cart.

**Course owner contract — nested, not flattened**: spec 11 planned to denormalize the instructor field by field (`owner_name`/`owner_avatar_url`/`owner_bio`), but commit `eca0a3d` reversed that. Today `CoursePopulated extends Course` with a nested `owner: { id, username, email, avatar_url, bio? }` (`course/models/course.interfaces.ts`, DTO `CoursePopulatedResponseDto` in `shared/models/api.interfaces.ts`), served by a **separate endpoint** `GET courses/detailed/:id` via `CourseService.getDetailedById`; plain `getById` stays flat. `CourseMapper` has two paths accordingly: `mapResponseToCourse` and `mapPopulatedResponseToCourse`. Read `course().owner.username` / `.owner.avatar_url` / `.owner.bio` — the flat `owner_*` fields do not exist.

**Course & library cards**: `course-mini-card` was replaced by `course-catalog-card` (+ a `course-catalog-card-skeleton` placeholder) for `explore-page`/carousels. Separately, `enrollment-mini-card` and the shared `shared/styles/mini-card-component.scss` were deleted in favour of `enrollment/components/library-course-card/`, which renders **two sibling markups** (`.view-grid` / `a.view-list`) toggled by CSS. Its model is `LibraryItem` in `enrollment/utils/library-item.util.ts` (`getEnrollmentStatus(progress)` → `not-started | in-progress | completed`). **Careful**: `totalLessons` and `nextLessonTitle` are **mocked** in that util — `totalLessons` is back-derived from `completedCount / (progress/100)`, or a stable per-course placeholder for not-started items, and `nextLessonTitle` is the literal `'[Título de la lección]'`. Neither comes from the backend.

**Teacher request**: `/become-teacher` was fully redesigned in `specs/10-*`. `TeacherRequestState` is wired (`myRequestResource` `rxResource` over `getMyTeacherRequest()`, `myRequest`/`isLoading` computeds, `submitRequest()` that `reload()`s on success, plus an `isSubmitting` signal for double-submit protection). The page switches between two layout families: blocking heroes (`role !== 'student'`, email not verified) and a two-column shell whose right panel swaps `teacher-request-form` ↔ `teacher-request-status` (pending/approved/rejected). The DTO shape (`categoryIds`, `aboutYou`, `experienceLevel`, `courseTitle`, `courseSummary`, `portfolioUrl`) is a **contract change the backend may not have yet** — the old `experience`/`motivation`/`courseIdea` fields are gone from this repo. `category-multiselect-dropdown` lives under `teacher-request/components/` on purpose; it's not meant as a reusable control.

**API/DTO boundary**: raw HTTP responses are never used directly in components — each feature that talks to the backend has a corresponding class in `src/app/mappers/` (e.g. `CourseMapper`, `AuthMapper`) that translates between backend shapes (`*Response`/`*DTO` types in feature `models/`) and app-internal model types. Follow this mapper pattern when adding new API integrations.

**HTTP & app config**: `provideHttpClient(withFetch(), withInterceptors([authInterceptor]))`. `authInterceptor` (`auth/interceptors/auth.interceptor.ts`) attaches `Authorization: Bearer <token>` from `UserState`'s token signal when present. `app.config.ts` also provides `LOCALE_ID: 'es-AR'` and `DEFAULT_CURRENCY_CODE: 'ARS'` with `registerLocaleData(localeEsAr)` — every `DatePipe`/`CurrencyPipe` in the repo depends on that, so don't format dates or money by hand. `environment.ts` / `environment.development.ts` hold `apiURL`, `MERCADOPAGO_PUBLIC_KEY` and `GOOGLE_CLIENT_ID`; the dev build swaps the file via `fileReplacements`.

**Cart**: `CartService` (`cart/state/cart.service.ts`) holds a `Cart` model (`Map<courseId, CartItem>`, quantity always 1 — no cupo selector and no coupon anywhere anymore, see `specs/09-*`), persists it to `localStorage` under the key `cart` via an `effect`, and recomputes `total` in a second `effect` that POSTs the items to `PaymentService.calculateTotal` (`payments/total`) — the total is always server-side, never summed in the client. `getItemsArray()` is the one place that maps `CartItem` → the backend's `ItemQuantity` shape (`id_course`/`title`/`unit_price` as string/`quantity`); every payment payload goes through it. `cart.component` renders as a full-height side panel (fixed, anchored right, `100vh`, see `specs/08-*`) using `CartPanelItemComponent`; its total animates via `animateNumber` (`@utils/animate-number.ts`, rAF tween, respects `prefers-reduced-motion`) into a local `animatedTotal` signal driven by an `effect` watching `cartService.total()`, while `subtotal` is a local `computed` off `cart().calculateTotal()`.

**Checkout flow**: `/payment/buy` is a 3-step wizard — `BuyPage` is the shell (`PageTitleComponent` + `CheckoutStepsComponent` + `<router-outlet>`) with children `cart` (default redirect) → `pay` → `confirmation`. `AuthenticatedGuard` protects the whole `buy` branch; `CartNotEmptyGuard` (`payment/guards/`) bounces `pay` back to `buy/cart` when the cart is empty. `PurchaseSummaryComponent` is the shared summary aside on `cart`/`pay`. `BuyConfirmationPage` reads the payment response from `history.state['payment']` (passed via `router.navigate(..., { state })`, deliberately not query params) and must handle `null` — a refresh loses it, which renders the "unknown" state rather than assuming success.

**MercadoPago (Fields API)**: `CheckoutFormState` (`payment/state/checkout-form-state.ts`) owns the whole SDK lifecycle: `loadMercadoPago()` + `new window.MercadoPago(publicKey)` in `initialize()`, then `mountFields()` creates/mounts the three secure iframes (`cardNumber`/`expirationDate`/`securityCode`) into DOM ids the component passes in. `FormCardCheckoutComponent` only owns the cardholder `FormGroup` and calls `initialize()`/`mountFields()` in `ngAfterViewInit` and `unmountFields()` in `ngOnDestroy` — **always unmount**, remounting over live fields breaks the SDK. All of `CheckoutFormState`'s state is `private _x = signal()` + `public x = computed(this._x)`; the only writes from outside go through `setAmount()` and `selectInstallments()`, and the component calls `reset()` in `ngOnDestroy` because the service is `providedIn: 'root'` and would otherwise carry the amount/error into the next checkout. The card number field's `binChange` event drives `mp.getPaymentMethods({bin})` then `mp.getInstallments({amount, bin})` to fill `paymentMethod`/`installmentOptions` signals; `submit()` calls `mp.fields.createCardToken(...)` and POSTs the order via `PaymentService.createOrder` (`orders/`) — **never log that payload**, it carries the card token, email and ID number. The SDK only ships types for `loadMercadoPago()`, so everything hanging off `window.MercadoPago` is hand-typed in `payment/models/mercadopago-fields.interface.ts` (`MPFieldInstance`, `MPPaymentMethodResult`, `MPPayerCost`) — extend that file instead of widening `any`. Field styling must be JS literals (`MP_FIELD_STYLE`) that mirror `variables.scss` tokens: the iframe can't read SCSS, custom properties or `clamp()`. `PaymentService.getAllPaymentMethods` is dead in this flow (methods are resolved client-side from the BIN).

**Order contract** (verified against `udemix-backend` `64ca194`): `POST /api/orders/` is a **single step** — the backend validates the flat body (`items`, `token`, `payment_method_id`, `payment_method_type`, `installments`, `payer`) with `OrderRequestAdapterDto.create`, recomputes the total from DB prices, creates the MercadoPago order, and creates the enrollments synchronously when the gateway returns `status === 'processed'`. There is no `orders/:id/pay`. The response is `ApiResponse<OrderUniqueResponse>` (the persisted payment: `id`, `id_payment` = MP order id, `status` = raw gateway status); `OrderMapper` (`mappers/order.mapper.ts`) translates it into the internal `Order` with `OrderStatus` = `'approved' | 'pending' | 'rejected' | 'unknown'`, which is what `BuyConfirmationPage` branches on. The backend's webhook (`POST /api/orders/notifications`) exists but isn't registered in the MercadoPago panel yet, so ticket payments (Rapipago/Pago Fácil) never get fulfilled.

## Styling

Global `src/styles.scss` plus per-component `.scss`. The only shared partial left is `auth/form-global.scss`, pulled in via `styleUrls: ['../../form-global.scss', './<name>.component.scss']` — **`src/app/shared/styles/` is empty** since `mini-card-component.scss` was deleted. `src/variables.scss` is the design-token source — import with `@use '@variables' as v;` and use its tokens rather than literals:

- Fonts: `$font-brand` (Playwrite DK Loopet), `$font-primary` (Montserrat)
- Colors: `$brand-color`, `$white-custom`, `$black-custom`, `$red-warning`, `$green-success`, `$yellow-caution`
- **Accessibility variants, with rules attached**: `$brand-color-deep` for brand-coloured *text* on light paper (the base brand is 4.2:1 and fails AA; deep is 6.3:1), `$brand-color-bright` for small text on the dark surfaces `#161616`/`#0e1a1a`, `$yellow-caution-deep` for caution *text* on light surfaces (base amber is 1.7:1 on white). Backgrounds and borders keep the base tokens.
- Breakpoints: `$breakpoints` map (`sm` 640, `md` 768, `lg` 1024, `xl` 1280, `laptop` 1366) consumed via the `bp-up($name)` / `bp-down($name)` mixins
- Fluid scales (`clamp()`, interpolated 320px→1280px viewport): `$text-sm`…`$text-display`, `$space-xs`…`$space-lg`
- Elevation & motion: `$shadow-surface-rest`, `$shadow-surface-hover`, `$shadow-chrome`, `$shadow-panel`, `$veil-border` (dark surfaces are elevated with a border, **not** a shadow), and `$lift-control: -3px` — hover lifts with `translate`, **never** `scale`. The `focus-ring($color, $offset)` mixin is mandatory for any control that sets `outline: none`.

Production budgets: 4kB warning / 8kB error per component stylesheet, 500kB/1MB initial bundle.
